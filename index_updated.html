Use Cases for HPC

  • HPC for everyone: A shared resource environment. Be mindful of your decisions.
  • Automated Job running: It is not an environment for active development!
  • Parallel computing tasks: Designed for scale, not for single-tasks.
  • Distributed Computing: Requires training but significantly shortens compute time.

Scalability: PC/Laptop to HPC

  • Be prepared to run the job on your laptop with a multi-core or hardware-accelerated setup first.
  • Start small and increase gradually!
  • The ultimate purpose is running compute tasks in a shorter time and in an optimized fashion.

Using Storage Efficiently

  • You don't need to write everything to disk. Jobs may produce a lot of data; keep only the important parts.
  • Frequently check your storage usage.
  • If data is no longer actively needed, please back it up somewhere else.

Accessing HPC

  • SSH Connection: A great way to communicate with HPC. Be aware that login nodes are not the place for running software remotely (e.g., VSCode, Codex, Copilot).
  • OpenOnDemand: Use this portal for interactive applications to run Jupyter Notebook, Matlab, and so on.

Building Scientific Workflows

Determine Entities and Duck-Type them on HPC

  • Scientific computing is a long run work. You will constantly add and remove pieces.
  • Reproducibility and maintainability must be doable at all stages.
  • Test on your PC and ensure the exact same setup is configured on the HPC environment.
  • Use management tools for automation, including Makefile or CMake.

Resource Allocation

How Much Is Needed?

  • This is the heart of HPC!
  • In the first few runs, it is difficult to estimate the optimal amount of resources. You must train yourself on this.
  • Your code should ensure that the allocated resources will be fully utilized!
  • Since HPC is resource-limited, it's crucial not to keep resources occupied if you're not using them. HPC is for everyone.

Data Transfer

Local to HPC or Remote to HPC

  • Data transfer is an important aspect of HPC.
  • Consolidate with the CRC team on how and what kind of data can be transferred or used.
  • HPC is not for personal data storage!
  • HPC is not for lab data storage!

Folder Setup for Jobs

  • The history of job submissions and their behavior easily helps you make better decisions for later ones.
  • Job outputs are important. Keep track of them and make sure the SLURM job gives the expected output.
  • Maintain a dedicated folder to keep your submitted job script and its corresponding output together.

Monitoring & Profiling

  • Debugging and profiling should be done on your PC first to make sure steps execute as planned.
  • Profiling is a great way to understand how your code runs on the hardware:
    • Resource consumption
    • Timing of algorithm steps
    • Identifying milestones (data write, bottlenecks, process operations)
