Getting In & Moving Data

  • SSH vs OpenOnDemand: Terminal access vs web-based GUI.
  • The Rule: Never run heavy compute on login nodes!
  • Moving Multi-TB Data:
    • Rsync: Good for small/medium syncs.
    • Globus: Essential for large-scale transfers.

Interactive vs. Batch

  • Interactive (salloc, OOD): Best for debugging, exploratory data analysis.
  • Batch (sbatch): The engine of HPC. Automated, unattended runs.

HPC is an orchestrated ecosystem, not just a bigger laptop.

Reproducible Workflows

  • Automate builds/runs using Makefile or CMake.
  • Containerization: Use Apptainer/Singularity.
  • Don't rely on hidden local dependencies. Package everything.
  • Test locally, deploy identical container on RANGE.

Resource Allocation Pitfalls

  • The 128GB vs 16GB Trap: Requesting max memory inflates queue time.
  • The "One-by-One" Trap: Running 1,000 simulations sequentially?
  • Solution: Slurm Job Arrays. Run concurrently!

Hardware Acceleration on RANGE

  • RANGE features NVIDIA H100 and H200 GPUs.
  • Common Error: Requesting 4 GPUs (--gres=gpu:4) for a single-GPU script.
  • Verify utilization using nvtop or nvidia-smi.

Storage & I/O Hygiene

  • Scratch is for Compute: Use high-performance VAST storage for fast I/O.
  • It is not a permanent lab archive.
  • Clean up intermediate files post-job.

Monitoring & Profiling

  • Profile locally or on a small subset first.
  • Review historical job data (seff ) to refine requests.
